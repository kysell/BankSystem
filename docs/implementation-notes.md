# Как устроена текущая реализация

Продолжено существующее решение ConsoleApp4.sln на .NET 10. Восемь проектов сохранены; исходный ConsoleApp4 и исходная миграция InitialBankSystem не переписаны. Отдельный оригинал учебного конспекта не найден: задания сверены с полным текстом №121 из сообщения пользователя. Сам конспект не добавлен в Git.

## Читаемость

Вместо большого Services.cs основные классы находятся в ClientService.cs, EmployeeService.cs, TestDataGenerator.cs и RateUpdaterService.cs. В Services.cs остались BankService, ClientFilter и собственное исключение. События и языковые примеры выделены по темам. Архитектурных слоёв или универсальных репозиториев не добавлено.

Конструкторы сервисов, моделей и контроллеров обычные: зависимости сохраняются в readonly-поля. Составные операции развёрнуты в последовательные шаги. Для Age, событий, reflection и преобразования DTO используются понятные переменные, if и foreach. Короткие методы вроде GetHashCode или Seconds остались короткими. LINQ оставлен там, где он показывает запрос или простую выборку.

Интерфейсы содержат только объявления операций. In-memory хранилища явно возвращают завершённый Task; Task.Run для словаря не нужен. EF-хранилища используют настоящие async-методы БД. Expression фильтр нужен, чтобы EF мог перевести его в SQL; обычная функция C# выполнялась бы в памяти.

## Модели и правила

Client/Employee сравниваются по неизменяемому Id; GetHashCode использует тот же Id. Account проверяет сумму и защищает баланс через lock. JSON восстанавливает вложенные счета, их идентификаторы, валюты и суммы через JsonInclude.

Client и Employee — разные наследники Person: cast не превращает клиента в сотрудника. BankService создаёт Employee и копирует поля. Currency — EF entity; CurrencyValue остаётся структурой для примера передачи по значению/ref.

RequestValidators используют FluentValidation. DTO mapping выполняется явно в App: для нескольких небольших моделей это проще чтения, чем дополнительная настройка AutoMapper. AutoMapper остаётся темой самоизучения из конспекта. Неверный PUT проверяется до изменения сохранённого объекта.

## Экспорт и ресурсы

CSV реализован через CsvHelper 33.1.0, как предусмотрено технологией задания. Удалён сложный ручной парсер кавычек. Заголовки/число столбцов/повторные Id проверяются; CR/LF, кавычки, запятые и UTF-8 проходят round-trip. Повторная запись обрезает старый файл. CSV содержит идентификационные поля клиента; при импорте сервис создаёт стандартный USD счёт. Импорт добавляет клиентов по очереди, общая транзакция всей партии не заявляется.

Generic JSON использует System.Text.Json для Client/Employee и вложенных счетов. BinaryFormatter не используется. Конвейер принимает IAsyncEnumerable, проверен bounded Channel. Размер файлов считается по UTF-8 байтам; слишком большая отдельная запись даёт ошибку. Имена файлов уникальны.

MemoryWorker использует SafeHandle: это сохранённая защита от утечки памяти, а не лишний архитектурный слой. Повторный Dispose безопасен. Тестовый TimeProvider нужен для проверки перехода месяца без реального ожидания.

## Асинхронность и конкурентность

RateUpdaterService.RunAsync явно запускается потребителем и ожидает границы календарных месяцев. Автоматически при старте API он не начисляет проценты. Нулевой баланс/процент не вызывает Deposit(0). Журнал начислений и восстановление после перезапуска не реализованы: это учебный цикл.

WithdrawManyAsync собирает задачи через foreach и ожидает WhenAll. Один scoped DbContext не выполняет конкурентные операции: SemaphoreSlim последовательно пропускает списания внутри одного хранилища. Между разными контекстами Amount — optimistic concurrency token; устаревшее обновление отклоняется. Отмена не откатывает уже завершённые списания; общей транзакции группы нет.

## База данных

BankSystemDbContext явно подключает четыре EntityConfigurations. Client→Accounts — обязательный FK с каскадом; Account→Currency — обязательный FK с запретом удаления используемой валюты. Проверяются amount>=0, salary>=0, exchange_rate>0.

Миграции: InitialBankSystem; EnforceAccountOwnership (NOT NULL/CHECK с отказом при старых orphan accounts); NormalizeCurrencies (перенос курсов до удаления старого столбца, обратный перенос в Down). Конфликтующие курсы не исправляются молча: миграция прерывается.

Проверено **на настоящем PostgreSQL 17**: Initial→latest→previous→latest, перенос/сохранение данных, SQL и ограничения, storage/CSV, API, Newman и NUnit HTTP fixture. Проверка создаёт только новый временный кластер и свои две базы. Последний каталог и результаты записаны в codex-progress.md; сервер остановлен. Существующие рабочие базы не затронуты.

SQLite in-memory остаётся быстрым набором реляционных тестов; не подменяет PostgreSQL проверки. sql/banksystem.sql использует отдельную схему banksystem_sql_practice; EF работает в public. Суммы группируются по валюте.

## API, Swagger и внешние сервисы

Без ConnectionStrings__BankSystem используются singleton хранилища памяти; при наличии строки — scoped DbContext и оба DB-хранилища. API сам не создаёт БД и не запускает миграции.

HTTP: 201+Location, 200, 204, 400, 404; конфликт обновления — 409; неожиданные ошибки — 500 без деталей внутреннего устройства. /openapi/v1.json обслуживается ASP.NET, Swagger UI — локальным NuGet-пакетом, CDN больше не нужен.

Настоящий Chrome проверил 10 операций и POST через Try it out; тестовая запись удалена. Rider debugger остановился на breakpoint контроллера, показал стек и DTO; сессия завершена, мой breakpoint удалён.

CurrencyService обращается к Frankfurter; тайм-аут не скрывается. Practice --currency-smoke печатает понятную ошибку и завершает работу с кодом 1 при проблемах сети. TeamService сверен с реальным публичным DEX OpenAPI: FoundationYear — int. Проверены fake auth/add/get/errors, сброс токена после failed reauth и запрет HTTP для передачи секретов. Live DEX остаётся внешним ограничением: anonymous HTTP GET=401, HTTPS certificate invalid. Подробности — dex-api-notes.md.

## Проверки, инструменты и Git

Обычные dotnet restore/build/test успешно выполнены вне ограничений sandbox. Результат: 67/67 тестов, 0 пропусков, build 0 предупреждений/ошибок. В PostgreSQL запуске дополнительно пройдены 3/3 NUnit HTTP cases. Newman: 12 запросов/14 assertions против памяти и PostgreSQL. Node runner остаётся запасным способом без зависимостей.

Newman/Playwright Core установлены только как локальные dev dependencies tools/node_modules; браузер и системные компоненты не устанавливались. Использован имеющийся Chrome с временным профилем. PostgreSQL/DataGrip/dotnet-ef уже были установлены. Docker не потребовался.

Локальный Git develop инициализирован после проверки файлов. .gitignore исключает сборки/IDE/отчёты/npm/секреты/БД. Сигнатур реальных секретов не обнаружено; ни commit, ни push, ни remote, ни публикация не выполнялись. Логи и TRX лежат в игнорируемой папке artifacts.
