- Team.FoundationYear приведён к integer/int32 по реальной опубликованной схеме DEX вместо неверного DateTime. Добавлен тест непустого списка команд и JSON добавления.

- Счёт с null-валютой даёт понятную ошибку валидации. Перевёрнутый диапазон дат сотрудников и слишком длинная должность отклоняются.

- Временный PostgreSQL скрипт проверен и дополнен отрицательными constraint probes, Newman и настоящими NUnit HTTP тестами с защитой от подключения к неучебной базе.

## Что упрощено и почему

1. **Models.cs:** Age вычисляется понятными шагами; конструкторы обычные; чтение/изменение баланса оформлено блоками. Проще объяснить значения, ссылки и lock.
2. **ClientService.cs / EmployeeService.cs:** отдельные файлы, readonly-поля, явные конструкторы, отдельные переменные загрузки/проверки/mapping/сохранения. Проще проследить один сценарий без вложенных await и throw-выражений.
3. **Abstractions.cs / Storages.cs:** интерфейсы только описывают операции; выполнение находится в конкретных классах. Убрана скрытая реализация методов интерфейса.
4. **Data:** EmployeeDbStorage вынесен в свой файл; поиск/копирование/сохранение разделены на шаги. BankSystemDbContext явно подключает четыре конфигурации вместо поиска классов через reflection.
5. **ExportService:** CsvHelper заменяет ручной парсер кавычек и переносов. Сохранены формат файла, проверки и граничные тесты.
6. **Events / LanguageExamples:** процентное сравнение, события, reflection и преобразования написаны через if/foreach с понятными именами.
7. **Исходники/тесты:** много действий в одной строке развёрнуто, добавлены фигурные скобки и простые русские комментарии. LINQ, generics из задания, EF Core, DI и async/await сохранены.

SafeHandle, SemaphoreSlim и TimeProvider оставлены: они обеспечивают корректное освобождение памяти, допустимую работу DbContext и быструю проверку месячного цикла. Новые архитектурные уровни не добавлялись.

## Действия пользователя — только обязательные

Для завершения **внешней авторизованной DEX-проверки** нужен актуальный HTTPS endpoint с корректным сертификатом и собственная учебная учётная запись. Их нельзя безопасно создать/угадать автоматически. Пароль и токен не нужно присылать в чат или сохранять в Git.

Получить безопасный адрес нужно у организатора курса; затем задать `TeamApi__BaseUrl` в Environment variables конфигурации Rider и локально выполнить AuthorizeAsync/GetTeamsAsync со своей учёткой. До этого нельзя отправлять пароль по HTTP или отключать проверку сертификата. Остальная инфраструктура и локальная демонстрация не требуют действий пользователя.

Для подготовки к собеседованию — самостоятельно прочитать и объяснить код по `docs/interview-preparation.md`. Это учебная работа над пониманием, а не оставшаяся ручная проверка инфраструктуры. Проект доработан с помощью Codex; владение кодом пользователем не предполагается автоматически.
