# Как объяснить BankSystem на Junior-собеседовании

Проект выполнен с помощью Codex по конспекту DEX-IT №121. Подготовка нужна, чтобы самостоятельно понимать и показывать код. Выполненные тесты не доказывают, что человек освоил тему.

## Проекты и путь запроса

Domain содержит данные и правила модели. App содержит действия над клиентами/сотрудниками, интерфейсы хранения, DTO и валидацию. Data реализует интерфейсы через память и EF Core. API принимает HTTP-запрос, получает сервис через конструктор и возвращает ответ. ExportTool пишет/читает файлы. Practice запускает упражнения; ConsoleApp4 — калькулятор. App.Tests проверяет приложение и API, Data.Tests — EF и месячные начисления.

При POST /api/clients ASP.NET читает JSON в ClientRequest. ClientsController.Create вызывает ClientService.CreateAsync. FluentValidation проверяет DTO. ToModel создаёт Client, затем AddClientAsync проверяет модель и добавляет USD-счёт. IClientStorage.AddAsync сохраняет клиента. В режиме памяти работает ClientStorage, при строке PostgreSQL — ClientDbStorage. DTO ответа возвращается с 201 Created и Location.

При EF сохранение выполняется в SaveChangesAsync. Where/OrderBy строят запрос; Count/ToListAsync отправляют SQL. SQL можно увидеть в выводе Data.Tests. DTO не раскрывает внутренний объект Client и его изменяемое состояние.

## 15 мест, которые нужно прочитать и объяснить

1. **Person** — общие свойства, Id и вычисление Age. Client и Employee наследуют Person.
2. **Account** — Deposit/Withdraw и lock вокруг общей суммы.
3. **BankService.UpdateEmployeeContract** — изменение объекта класса; рядом UpdateCurrency показывает копию struct и ref.
4. **TestDataGenerator.CreateRandomClients** — последовательные правила Bogus, тестовые данные.
5. **IClientStorage** — интерфейс и расширение обобщённого IStorage<Client>.
6. **ClientStorage** — Dictionary, поиск и блокировка коллекции.
7. **ClientService.AddClientAsync** — проверка, USD по умолчанию, сохранение.
8. **ClientDbStorage** — EF CRUD, фильтр/пагинация, сохранение счетов.
9. **BankSystemDbContext.OnModelCreating** — четыре конфигурации и связи таблиц.
10. **ClientsController.Create** — DTO на входе, сервис через DI, 201 на выходе.
11. **DtoMapping.ToModel** — явное копирование полей запроса в модель.
12. **ClientRequestValidator** — правила входных данных; отдельная проверка модели защищает CSV/прямые вызовы.
13. **RateUpdaterService.RunAsync** — начало следующего месяца, Task.Delay, CancellationToken.
14. **ExportService.ExportJsonAsync<T>** — generics, using, JSON и путь к файлу.
15. **SimpleCalculator** — четыре операции и проверки результата/ошибок.

После этого прочитайте CurrencyService.ConvertAsync: HTTP GET, EnsureSuccessStatusCode, JSON, расчёт суммы. Посмотрите ClientFilePipeline и три класса событий. Это небольшие отдельные упражнения курса, их не нужно смешивать с логикой создания клиента.

## Рассказ примерно на две минуты

«Это учебная банковская система по конспекту DEX. Я разбираю её с помощью автоматических тестов и отладчика. В Domain находятся модели клиента, сотрудника и счёта. App проверяет данные и выполняет действия, а Data хранит их в памяти или PostgreSQL через EF Core. API получает сервис через конструктор, работает с DTO и возвращает стандартные HTTP-коды.

При создании клиента проверяются возраст и паспорт, добавляется долларовый счёт, затем клиент сохраняется. Для выборок используется LINQ. В EF запрос выполняется при материализации или агрегате; миграции меняют схему. Отдельно реализованы CSV/JSON, HTTP-конвертация валют, события и потоковые упражнения. Калькулятор находится в отдельном консольном проекте.

Я могу показать создание клиента в Swagger, тесты, SQL EF и объяснить lock/async/cancellation. Это учебная программа: я не выдаю её за готовый банковский продукт. Сложные производственные функции сюда специально не добавлялись».

## Ограничения демонстрации

Исходный Git-процесс курса требует преподавателя/репозитория для fork и PR. В этой работе сохранён локальный commit, публикация не выполнялась. Postman-коллекция проверена Newman, но импорт cURL из браузера и OpenAPI в GUI ещё нужно пройти лично. DEX TeamService был примером автора и удалён; для практики CurrencyService аккаунт DEX не нужен.
