# Почему оставлены эти компоненты

Требования и цитаты первоисточника находятся в requirements-audit.md. Оригинал PDF №121 найден в Downloads; старые документы проекта не использовались как доказательство.

## Структура

Data → App → Domain прямо указан на стр. 58. DTO, DI и валидаторы предусмотрены на стр. 123; это не добавленная нами сложная архитектура. IClientStorage расширяет IStorage<T>; IEmployeeStorage повторяет подход для сотрудников. Конкретные классы хранят данные в словаре либо EF Core. Никаких дополнительных mediator/factory/repository-слоёв не добавлено.

ConsoleApp4 — отдельный калькулятор из самостоятельного задания стр. 142. BankSystem.Data.Tests добавлен по стр. 113 для тестирования инфраструктуры и месячного начисления; App.Tests проверяет приложение/API/упражнения. Всего 9 проектов, из них 2 тестовых и 2 консольных.

## Читаемость

BankService, клиентский и кадровый сервисы выполняют действия последовательными шагами. Контроллер получает DTO, вызывает сервис и возвращает HTTP-код. DTO — небольшие record-контейнеры; mapping явно перечисляет поля. FluentValidation проверяет входные DTO, PersonValidation защищает сценарии создания напрямую и CSV-импорта. Дублирующие DataAnnotations удалены.

TestDataGenerator использует обычные циклы и последовательные правила Bogus. LINQ сохранён для выборок, сортировки и SQL-трансляции: изучение этих операций прямо входит в курс. Expression<Func<T,bool>> нужен, чтобы один контракт фильтра работал и в памяти, и в SQL; это не произвольная лишняя абстракция.

RateUpdaterService вычисляет задержку до следующего месяца UTC, ожидает Task.Delay и начисляет проценты через storage. Отмена передаётся вниз. Самодельных часов/таймеров в проекте больше нет. Тесты проверяют календарь, отмену ожидания и сохранение суммы отдельно; реальный месяц в тесте не ожидается.

## Корректность обязательных упражнений

- Client/Employee — отдельные потомки Person. Превратить Client в Employee обычным cast нельзя; BankService создаёт Employee и копирует данные. В Practice остаются is/as и числовое приведение.
- CurrencyValue — структура раннего задания. Currency — класс позднего задания со звёздочкой и таблица БД.
- Равенство клиентов/сотрудников определяется по неизменяемому Id; hash использует тот же Id. Коллизия hash допустима.
- Account защищает баланс lock. EF Amount имеет concurrency token, чтобы отвергать устаревшую запись; SemaphoreSlim защищает один DbContext от одновременных списаний. Удаление этих небольших защит ломало бы корректность задания с параллельными запросами.
- Миграции и SQL не переписывались ради стиля. Нельзя удалять таблицы рабочей БД; verifier создаёт отдельный кластер.
- ExportTool использует CsvHelper для правильного CSV с кавычками/переносами. using освобождает файлы и покрывает совмещённую практику IDisposable. JSON обобщённый, восстанавливает вложенные счета.
- ClientFilePipeline читает поток клиентов и ротирует файлы по UTF-8 байтам. Асинхронный вход/канал нужен для конвейера, а не для дополнительного банковского функционала.

## Библиотеки

Bogus прямо требуется в самостоятельном задании стр. 33; FluentValidation назван на стр. 123; CsvHelper используется в разделе Stream. EF Core/Npgsql нужны для PostgreSQL; SQLite находится только в Data.Tests, чтобы проверять хранилища без постоянного сервера. Swagger UI нужен для P15; Newman запускает настоящую Postman-коллекцию.

AutoMapper и атрибуты Newtonsoft упомянуты как темы для изучения. Внедрение AutoMapper не обязательно для явного mapping из задания. JSON-практика не требует конкретной библиотеки; используется уже имеющийся System.Text.Json. XML/BinaryFormatter — теоретические примеры, реализации не добавляются.

## Удалено

TeamService с AuthData/AuthResponse/Team/TeamResponse; MemoryWorker с SafeHandle; WordCount; PrintObjectProperties; неиспользуемый overload ref Currency; самодельные часы/таймер/storage-декоратор тестов; дублирующая проверка пополнения; самописный Postman runtime; Playwright script/dependency; лишний DTO CurrencyConversion; неиспользуемый overload поиска EmployeeService.SearchAsync. CurrencyService возвращает decimal, обязательный поиск сотрудников сохранён. Ни одному из удалённых авторских примеров/дополнительных инструментов не назначен статус обязательного незавершённого задания.

## Границы

Это учебный API без входа пользователей, финансового ledger и распределённого scheduler. CSV-импорт не является транзакцией всего файла, поэтому ошибка поздней записи не откатывает предыдущие. Фоновый цикл запускается явно и не гарантирует ровно одно начисление после перезапуска приложения. Такие дополнительные производственные задачи конспектом не заданы.
