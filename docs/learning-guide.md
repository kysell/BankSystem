# Как пройти проект по конспекту

Команды находятся в README, страницы и цитаты — в requirements-audit.md, объяснение классов — в interview-preparation.md.

## Порядок работы

1. Запустите Practice и объясните каждую строку: ООП, struct/ref, приведение, Stopwatch, словарь, LINQ, события.
2. Откройте BankService и модели Domain. Найдите разницу копирования struct и ссылки class.
3. Прочитайте ClientService и IClientStorage. Проследите validation → default USD → AddAsync.
4. Сравните ClientStorage с ClientDbStorage: тот же интерфейс, другая реализация.
5. Запустите тесты Data.Tests. Они выводят SQL команд EF; Where формирует выражение, Count/ToList выполняют запрос.
6. Запустите API, откройте Swagger, создайте клиента и проследите DTO → сервис → storage. Повторите для сотрудника.
7. Прочитайте ExportService: using, CSV и generic JSON; затем тесты round-trip.
8. Прочитайте ThreadAndTaskTests и RateUpdaterServiceTests. В ThreadAndTaskTests находятся тесты потокобезопасного пополнения счёта и конвейера. Объясните lock, ожидание и отмену.
9. Запустите ConsoleApp4 и тесты четырёх операций калькулятора.

## Единственный неподтверждённый шаг основной практики: Postman GUI

На машине приложение Postman не найдено; установка системного приложения и вход в ваш аккаунт требуют вашего участия. Newman уже проверяет цепочку коллекции, но он не доказывает процедуру импорта на стр. 134.

После установки/открытия Postman:

1. Запустите BankSystem.Api на localhost:5000. В браузере откройте /swagger, выполните GET списка клиентов. В DevTools → Network выберите запрос → Copy → Copy as cURL.
2. В Postman нажмите Import → Raw text, вставьте cURL → Import → Send. Ожидается 200 и JSON-массив.
3. Import → Link → http://localhost:5000/openapi/v1.json. Убедитесь, что появилась схема с методами клиентов и сотрудников.
4. Для сценария используйте отдельную готовую коллекцию postman/BankSystem.postman_collection.json и окружение BankSystem.postman_environment.json; запустите Runner. Ожидается 12 запросов, 14 успешных проверок. Посмотрите записи в Postman Console.

Не нужно получать аккаунт DEX: TeamService на стр. 126–130 является объясняющим примером, а практика на стр. 131 требует CurrencyService. Amdoren — разрешённый вариант, Frankfurter выполняет ту же задачу.

Внешний Git-процесс (fork/PR/review преподавателя, стр. 5–6) возможен только с репозиторием/рецензентом курса и отдельным разрешением на публикацию. Он не заменяется локальным commit.

## Вопросы для самостоятельного изучения

Изучить AutoMapper означает понять сопоставление DTO/модели; в этом проекте оно сделано явно. Изучить Newtonsoft-атрибуты означает разобраться в JsonIgnore и управлении JSON-полями; наши рабочие JSON-методы используют стандартный System.Text.Json. Parallel.For/ForEach сравните с обычным циклом на изолированном примере без изменения баланса.

В старом конспекте есть упрощения: struct не обязательно находится в стеке; Task не равен потоку; await не обещает новый поток; IEnumerable не гарантирует отложенность; разные объекты могут иметь одинаковый hash; Dispose освобождает ресурс, а не уничтожает managed-объект. Тесты подтверждают поведение программы, но не освоение материала пользователем.
