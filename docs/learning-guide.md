# Как запускать и изучать проект

Команды запуска и проверки приведены в [README](../README.md). Разбор кода, 20 вопросов и двухминутное объяснение находятся в [interview-preparation.md](interview-preparation.md).

## Уже выполнено автоматически

- Временный PostgreSQL: SQL, ограничения, миграции вверх/вниз/вверх, storage, CSV, API, Newman и 3 HTTP-теста NUnit. Рабочие базы не затронуты, сервер остановлен.
- SQLite, экспорт CSV/JSON, отмена, месячный цикл с виртуальным временем и потокобезопасность — в общей тестовой сборке.
- Swagger открыт в настоящем Chrome; проверены 10 операций и Try it out. Файлы UI обслуживаются локально.
- Rider debugger: реальный запрос остановлен на breakpoint, просмотрены стек и DTO. Сессия остановлена, созданный агентом breakpoint удалён.
- Postman-коллекция выполнена настоящим Newman: 12 запросов, 14 assertions, без ошибок. Повторять те же проверки вручную в GUI необязательно.
- Локальный Git подготовлен без коммитов и публикации; README и исключения созданы.

Для повторения PostgreSQL проверки достаточно `bash tools/verify-postgres.sh`. Скрипт не ставит программы и не использует существующие базы. Newman запускается дополнительно, если установлены локальные tools dependencies.

## Действия пользователя — только обязательные

Для **live-проверки DEX** нужен корректный HTTPS endpoint с доверенным сертификатом и собственная учебная учётная запись. Автоматически создавать выдуманный аккаунт или передавать пароль по HTTP нельзя. Проверенный старый HTTP адрес требует Bearer (401), а HTTPS не проходит проверку сертификата.

Получите актуальный безопасный адрес у организатора курса. В Rider откройте Run → Edit Configurations → BankSystem.Api → Environment variables и задайте `TeamApi__BaseUrl`. AuthData со своими данными передавайте только локально при вызове AuthorizeAsync. Не сохраняйте пароль/токен в исходники, Git или переписку. До появления рабочего HTTPS адреса live-авторизацию выполнять не нужно.

Это единственный внешний остаток №23. Для локальной технической демонстрации BankSystem учётная запись DEX не нужна. Детали опубликованной схемы и тестов — [dex-api-notes.md](dex-api-notes.md).

## Самостоятельная проверка понимания

Это учебные упражнения, а не обязательные действия для исправления инфраструктуры:

1. Запустите Practice и найдите в коде причину каждой строки вывода.
2. Создайте клиента через Swagger. Найдите место в ClientService, где появляется USD-счёт.
3. Поставьте свой breakpoint на CreateAsync, запустите API в Debug, проследите путь DTO→Client→storage.
4. Измените одно правило валидации и соответствующий тест; объясните результат.
5. Запустите 2 потока пополнения и объясните, почему без lock можно потерять изменения.
6. Сравните обычный список и EF query: где выполняются Where и ToList?
7. Ответьте на 20 вопросов интервьюера без подсказок и проверьте ответы по коду.

## Уточнения к старому конспекту

- Struct не обязательно лежит в стеке: его место зависит от содержащего объекта/массива/переменной. При присваивании копируется значение; у class — ссылка.
- Boxing создаёт копию значения; unboxing требует соответствующего типа. Это не простое перемещение из стека в кучу и обратно.
- Task не равен потоку; await не обязан продолжать работу в новом потоке. Для ожидания I/O отдельный рабочий поток часто не нужен.
- CancellationToken — кооперативная отмена, а не принудительное завершение и не rollback.
- IEnumerable сам по себе не обещает ленивость. Where обычно отложен, ToList материализует.
- Равные объекты обязаны иметь одинаковый hash; разные объекты могут иметь одинаковый hash. Hash не постоянный идентификатор. Ключ словаря должен сохранять поля равенства.
- События требуют внимания к срокам жизни объектов. Сам цикл ссылок не запрещает сборщику мусора освободить оба объекта.
- Dispose освобождает ресурсы, но не уничтожает managed объект. finally не гарантируется при принудительном завершении процесса.
- Нельзя складывать номинальные суммы разных валют без преобразования.

Успешные тесты подтверждают сценарии, но не подтверждают освоение материала пользователем. Перед демонстрацией полезно самому воспроизвести путь создания клиента и объяснить ограничения проекта.
