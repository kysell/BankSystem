## Как считаются задания

В оригинале нет сквозных номеров заданий. Обнаружено **20 заголовков «Практическая часть»**, из них два только отсылают к другой теме: делегаты (стр. 27 → List/Dictionary) и IDisposable (стр. 84 → Stream). Получается **18 самостоятельных блоков практики P01–P18**. Ещё **14 отдельных поручений написать код в «Самостоятельно» S01–S14** и **2 дополнительных блока O01–O02**. Итого 32 основных пункта реализации и 2 дополнительных. Это счёт блоков, а не каждого метода: повторная ссылка P18 на P04 оставлена как отдельный пункт оригинала. Теоретическое «изучить» не приравнивается к написанию ещё одного сервиса.

Ни прежние 26 пунктов, ни наши отчёты не служат источником требований. Следующие таблицы составлены по PDF; завершённость уточняется проверками кода. Ручные действия не объявляются выполненными по наличию теста.

- Удалить TeamService, AuthData/AuthResponse/Team/TeamResponse, DI-регистрацию и только их тесты: P16 требует CurrencyService.
- Удалить MemoryWorker/SafeHandle и два теста этого авторского примера. Using/IDisposable проверяются файловыми заданиями P11/P12/P14.
- Удалить WordCount, PrintObjectProperties и неиспользуемый UpdateCurrency(ref Currency); сохранить int.Seconds, reflection задания и упражнение со struct.
- Удалить собственный упрощённый Postman runtime и браузерную обвязку Playwright. Сохранить коллекцию и настоящий Newman; сохранить безопасный PostgreSQL verifier для P08–P10.
- Упростить проверку месячного цикла: отдельное вычисление задержки до следующего месяца и обычный Task.Delay; удалить самодельные TimeProvider/ITimer и storage-декоратор теста. Календарный расчёт, отмена ожидания и сохранение начислений проверяются отдельно; реальный месяц в тесте не ожидается.
- Сохранить Domain/App/Data/API/ExportTool/Practice/App.Tests. Пустой ConsoleApp4 использовать для настоящего S14, добавить прямо названный на стр. 113 проект Data.Tests для EF/фоновых тестов. Это учебные проекты, не дополнительные слои.
- Сохранить DbContext/конфигурации/миграции, memory+EF storage, DTO/валидаторы/DI, CsvHelper/Bogus/FluentValidation, lock/SemaphoreSlim: они обслуживают конкретные пункты выше. SQLite — только тестовая база; PostgreSQL остаётся целевой СУБД.

Проверки и итоговая завершённость фиксируются в practice-checklist.md и completion-report.md после каждой группы изменений.

## Подтверждение выполнения ревизии

Решения выше внесены в код. App.Tests содержит 50 сценариев, Data.Tests — 12. Удалены 5 сценариев DEX и 2 сценария MemoryWorker; объединены два теста одного пополнения. Сложный единственный тест календаря заменён тремя проверками календарных дат и одной проверкой отмены ожидания. Исходные 67 сценариев поэтому нельзя напрямую сравнивать с нынешними 62: обязательные операции не отключались.

Пункт P10 дополнительно выполнен в настоящем Rider debugger: остановка на ClientDbStorage.Search перед Count; query — EntityQueryable; step over Count дал 12; step over Skip/Take/ToList создал List из 5 клиентов. Прогон соответствующего теста завершился успешно, breakpoint агента удалён, сессия stopped. Для P17 приложения Postman на машине не найдено, CLI не подменяет ручной импорт из пункта 1.

Дополнительно удалены лишний результат-DTO CurrencyConversion (ConvertAsync возвращает decimal) и неиспользуемый EmployeeService.SearchAsync. Обязательный поиск сотрудников через API и storage остался. Финальные результаты: restore/build успешны, 62/62 тестов; отдельный PostgreSQL verifier успешен, Newman 12/14; Practice/калькулятор и настоящий CurrencyService запущены.
